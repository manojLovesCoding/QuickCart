Inngest & Clerk User Synchronization

Technical Documentation | Next.js | MongoDB | Clerk | Inngest

1. Introduction

This module integrates Clerk authentication with MongoDB using Inngest. It automatically synchronizes user information whenever a user is created, updated, or deleted in Clerk.

Inngest listens for Clerk webhook events and executes the corresponding functions to keep the application database synchronized.

2. Technologies Used

  • Next.js: Application framework.
  • Clerk: User authentication and management.
  • Inngest: Event-driven background function execution.
  • MongoDB: Database for storing user information.
  • Mongoose: MongoDB object modeling.

3. System Workflow

The synchronization process works as follows:

Clerk
→
Event
→
Inngest
→
Function
→
MongoDB

Workflow Explanation

  1. A user performs an action in Clerk.
  2. Clerk generates an event.
  3. Inngest receives the event.
  4. The matching Inngest function executes.
  5. User information is created, updated, or deleted in MongoDB.

4. Inngest Client Configuration

export const inngest = new Inngest({
  id: "quickcart2-next"
});

This creates an Inngest client for the QuickCart2 Next.js application. The client is used to register background functions and handle events.

  • Inngest imports the Inngest SDK.
  • id uniquely identifies the application.

5. User Creation Function

Event: clerk/user.created
Function ID: sync-user-from-clerk

This function executes whenever a new user is created in Clerk. It extracts the user's information and saves it to MongoDB.

Data Extracted

  • User ID
  • First name
  • Last name
  • Email address
  • Profile image URL

Database Operation

const userData = {
  _id: id,
  email: email_addresses[0].email_address,
  name: first_name + " " + last_name,
  imageUrl: image_url,
};

await connectDB();
await User.create(userData);

The extracted information is converted into a MongoDB user document. The Clerk user ID is used as the MongoDB document ID.

6. User Update Function

Event: clerk/user.updated
Function ID: update-user-from-clerk

This function executes whenever an existing user updates their profile information in Clerk.

Database Operation

await connectDB();

await User.findByIdAndUpdate(id, userData);

The function connects to MongoDB and searches for the user using their Clerk ID. It then updates the stored user information.

7. User Deletion Function

Event: clerk/user.deleted
Function ID: delete-user-from-clerk

This function executes whenever a user account is deleted from Clerk. It removes the corresponding user document from MongoDB.

Database Operation

const { id } = event.data;

await connectDB();
await User.findByIdAndDelete(id);

The Clerk user ID is used to locate and delete the corresponding MongoDB document.

8. Event Summary

Event Function Database Action
clerk/user.created syncUserCreation Create user
clerk/user.updated syncUserUpdation Update user
clerk/user.deleted syncUserDeletion Delete user

9. MongoDB User Data Structure

The following table describes the user information stored in MongoDB.

Field Description
_id Unique Clerk user ID.
email User's email address.
name Combined first and last name.
imageUrl User's profile image URL.

10. Important Notes

  • Make sure MongoDB is properly connected before database operations.
  • Configure Clerk webhooks to send events to the Inngest integration.
  • Ensure the Inngest functions are registered with your application.
  • Handle missing email addresses and optional profile fields safely.
  • Use appropriate error handling and logging for production.
Code improvement: In your original creation function, use await connectDB(); before await User.create(userData);. Passing the result of User.create() into connectDB() is likely unintended. Also consider using an upsert for user creation to handle event retries safely.

11. Conclusion

This Inngest integration provides automatic synchronization between Clerk and MongoDB. It ensures that user information remains consistent across the authentication system and application database.

By using event-driven functions, the application can manage user creation, profile updates, and account deletion without manually performing database operations.
